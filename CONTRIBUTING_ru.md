# Вклад в Amber Guard Laboratory

Спасибо за интерес к проекту! Перед внесением изменений, пожалуйста, прочитайте это руководство.

## Процесс внесения изменений

1. Форкните репозиторий
2. Создайте ветку фичи: `git checkout -b feature/my-feature`
3. Внесите изменения с тестами
4. Прогоните обязательные гейты:
   ```bash
   go build ./... && go vet ./... && go test ./...
   bash scripts/i18n_gate.sh
   gofmt -l .
   ```
5. Закоммитьте с понятным сообщением (рекомендуется Conventional Commits: `feat(scope): ...`, `fix(scope): ...`, `docs: ...`)
6. Создайте Pull Request

## Стандарты кода

- Go 1.21+ (только Linux)
- Все пользовательские строки живут в `i18n/` (никакого хардкода); `TrEvent`/`TrEventf` никогда не оборачиваются в `fmt.Sprintf`
- Ошибки обрабатываются, не игнорируются
- Комментарии: на русском для внутренней логики, на английском для публичного API (`// PURPOSE:`, `// CONTRACT:`, `// SIDE-EFFECTS:`); каждый значимый блок — с заголовком `// === ... ===`
- Внешние команды только через `sys.RunTimeout` / `sys.RunTimeoutStreamed`; прямой `exec.Command` в бизнес-коде запрещён
- Мутации конфига только через `config.Update()` (клон снепшота + атомарная запись); опубликованный `config.C` напрямую не мутируется
- Пути только через генераторы/константы из `config/paths.go` (без хардкода путей)
- Слоистость: `tui/` только отображает; бизнес-логика живёт в `internal/service/` (мост) и пакетах-протоколах (`internal/armor`, `internal/tarpit`, `internal/tarpitctl`, `internal/maintenance`)
- Маркеры состояний создаёт/удаляет только демон; клиенты пишут только декларацию
