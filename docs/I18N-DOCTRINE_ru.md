# Доктрина AGL i18n (задача 6.7)
**Статус:** активна. **Область применения:** все пользовательские строки комплекса.

### 1. Границы контейнеров
* `UITranslation` (`i18n/lang_*_ui.go`): всё, что видит человек (экраны TUI, окна прогресса, подсказки в консоли, страница web-rescue, подписи матрицы настроек).
* `LogTranslation.Events` (`i18n/lang_*_logdescr.go`): удобочитаемые описания журнала, привязанные к машинным кодам событий.

**Только код (никогда не добавляется в словари):** идентификаторы, теги маршрутизации, разметка termui (`(fg:...)`, `[[ ... ]]`), геометрия (ширина `%-Ns`, разделители `│`, отступы), пути файловой системы, buildinfo/версия, глаголы протоколов (ON/OFF), коды событий.

### 2. Правило разметки и геометрии (решение аудитора)
Скелеты таблиц и разметка живут в коде; словари содержат только переводимый текст.
* **Обоснование:** ошибка переводчика не должна ни обрушивать среду выполнения (runtime), ни ломать верстку; длины подписей на RU/EN различаются по замыслу.
* Базовые значения, созданные до принятия доктрины и до сих пор содержащие разметку внутри (например, `CoreSysConsoleBody`), являются замороженным наследием (legacy); новые правки не должны добавлять разметку в словари.

### 3. Изоляция модулей и именование ключей
Один исходный модуль = собственный префикс ключа; идентичный текст **НЕ** переиспользуется между модулями.
* **Формула именования (аудитор):** `View + Screen + Component + Purpose` (пример: `ViewTrapCardHintTitle`).
* Поля сгруппированы по исходным файлам с помощью маркеров `// --- <file> ---`.

### 4. Коды событий и контракт журнала (A.2)
* `LogAction`/`TrEvent`/`TrEventf`: код — это машинный ключ; описание локализуется; динамические данные попадают в отдельное поле `details`.
* **Фолбэк (резервный вариант):** неизвестный код или пустой шаблон → возвращается сам машинный код; строка журнала никогда не бывает пустой (покрывается тестом `TestTrEventFallback`).
* Никогда не оборачивайте `TrEvent`/`TrEventf` в `fmt.Sprintf` (ловушка двойного форматирования); контролируется скриптом `scripts/i18n_gate.sh`.
* Коды событий журнала семантические, а не привязанные к модулям: одно и то же событие, залогированное разными модулями, использует **ОДИН** код; источник определяется по столбцам COMPONENT/ACTION (пример: `config.reload_failed` от TARPIT_MANAGER и от watcher/наблюдателя). Изоляция модулей (§3) применяется к UI-строкам, а не к кодам журнала.
* Записи журнала после инициализации (post-init) идут через `sys.LogAction` + коды событий; использование сырых `log.Println`/`log.Printf` с естественным языком **запрещено** после `i18n.InitLanguage`. Диагностика при загрузке (до init) является исключением и пишется на техническом английском вне словарей (showAlertScreen, проверка root, предупреждение logrotate).

### 5. Форматирование ошибок
* Присутствует `%w` → `fmt.Errorf(i18n.T.Field, args)`.
* Нет глаголов (verb) → `fmt.Errorf("%s", i18n.T.Field)` (формат константы, безопасный для vet).
* Аргументы без `%w` → `fmt.Errorf("%s", fmt.Sprintf(i18n.T.Field, args))`.

### 6. Грамматика заголовков (соглашение TD-6; ретроактивная унификация = WON'T-FIX)
* **Экраны мониторинга:** обычный заголовок `" Name "`.
* **Модальные окна / редакторы / окна транзакций**, а также заголовки с метаданными (`│`, порт, тег): в скобках `" [ ... ] "`.
* Историческая несогласованность (ARMOR/CORE в скобках против MAIN/TARPIT без них) заморожена решением; все новые экраны следуют правилу выше.

### 7. Шлюзы и гигиена (контроль качества)
* `scripts/i18n_gate.sh`: проверки с нулевой терпимостью (никаких двойных Sprintf вокруг TrEvent, никаких устаревших хелперов настроек, никаких алиасов Translation/Languages, никаких `isEn`, никаких `LabelRu`/`LabelEn`) + `go build/vet/test ./...` + диагностика gofmt.
* `i18n/i18n_test.go`: паритет RU/EN, непустые значения, полнота SysctlDocs, фолбэк TrEvent/TrEventf.
* `.gitignore`: артефакты сборки (`/agl`, `/amberguard/`).

### 8. Политика коммитов и истории
* Conventional commits (соглашение о коммитах); одна логическая область (scope) на коммит.
* Коммит может быть изменен (amended) только пока он находится на вершине ветки; после этого история неизменяема, а истинное распределение областей (scope) живет в описании PR / заметках о релизе.
