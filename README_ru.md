# Amber Guard Laboratory

**Проект:** Автономный оборонный комплекс для Linux-хоста на Go 1.21+. Единый бинарник `agl`, три демон-режима + интерактивная TUI-панель.

**Ключевые контуры:**

- **Дегтярная Яма (Tarpit)** — базовая ловушка на порту 22 + пул мульти-ловушек, управляется единым демоном через декларативный инвентарь
- **Броня периметра (Armor)** — rate-limit рубежи через UFW, авто-обнаружение служб, тюнинг ядра (sysctl)
- **Рокировка портов (Castling)** — переезд SSH на скрытый порт с бэкапом и откатом
- **Канал спасения (Web Rescue)** — HTTPS-сервер веб-стука (псевдо-2FA), три уровня защиты (опции A, B, C)
- **Наблюдатель простоя (Watcher)** — испепеление временных дверей по таймауту
- **Автообновление сервера** — oneshot apt-get dist-upgrade через systemd-таймер
- **Форензика и инвентаризация** — сканирование `/proc`, `ss`, корреляция

**Архитектурные принципы:** декларативность, fail closed, трёхфакторный статус, слоистость (TUI → service → protocol), полная автономность, i18n через словари, внешние команды только через `sys.RunTimeout`, мутации конфига только через `config.Update()`, пути через `config/paths.go`.

## Сжатая характеристика комплекса

**Amber Guard Lab. (AGL)** — автономный оборонный комплекс для Linux-хоста (Ubuntu/Debian; Go, TUI, один бинарник). Не «замок на двери», а экосистема активной обороны: обнаруживает, обманывает, истощает, защищает, спасает и собирает цифровые отпечатки (метрики) атакующего (30 параметров).

## Возможности

- **Дегтярная Яма (Tarpit)** — SSH-ловушка с вариативными задержками; базовый капкан на порту 22 + декларативный пул мульти-ловушек под управлением единого демона.
- **Броня периметра (Armor)** — авто-обнаружение служб и rate-limit рубежи UFW с корпоративными сигнатурами; самовосстановление после ребута через контур сверки (Reconcile Armor).
- **Рокировка портов (Castling)** — переезд SSH на скрытый порт с авто-бэкапом, откатом, аварийным люком локальной петли и правилом доступности перенесённого порта (наследует тип доступа порта 22). Замок: рокировка отклоняется при живой броне на порту 22.
- **Канал спасения (Web Rescue)** — автономный HTTPS-сервер веб-стука (веб-шлюз) с TLS 1.2+ и bcrypt-паролем: вход даже при закрытом периметре. Три уровня защиты:
  - **Опция A** (`ssh_allow_in_from_ip`): постоянная дверь админа — whitelist IP на скрытом порту.
  - **Опция B** (`ssh_ip_web_knock`): веб-стук с испепелением временных дверей по таймауту простоя. Требует опцию A.
  - **Опция C** (`web_https_panel_active`): доступность веб-панели (маршрут `/panel`).
  - Канал активен только при совпадении: рокировка ∧ включённый HTTPS-сервер ∧ включённая опция B.
  - Криптографические префиксы маршрутов (12 hex-символов): `/хэш/rescue`, `/хэш/panel`.
- **Наблюдатель простоя (Watcher)** — детекция сессий через `/var/run/utmp` и «испепеление» временных дверей при простое администратора. Жизненный цикл следует за физическим сервером (`web_server_enabled`); при выключенном сервере процесс завершается сам.
- **Форензика** — SIEM-хроника касаний и истощения: страны (GeoIP), поведение, расширенные TCP-отпечатки сканеров (30 колонок: MSS, RTT, ретрансмиты, IAT-статистика, бакеты размеров чтений, причина завершения).
- **Автообновление сервера (v8.4.0)** — автономный суточный цикл обновлений ОС (`apt-get dist-upgrade` в noninteractive-режиме), детекция необходимости ребута и отложенная перезагрузка; планируется systemd-таймером, декларативно включается из SETTINGS.
- **Резервное копирование (v8.4.0)** — асинхронная генерация трёх файлов сессии (системный снапшот, список пакетов, форензика-логи) с FIFO-ротацией при дефиците места. Цели настраиваются через `/etc/amberguard/backup_targets.json`.

## Требования

- **ОС:** Ubuntu 22.04+ / Debian 12+ (systemd, UFW, Netfilter)
- **Go:** 1.21 или новее (только Linux)
- **Права:** root (привилегии для привязки портов < 1024 и управления systemd)
- **Опционально:** `geoip-bin` + `geoip-database` (страны в логах; устанавливается автоматически при первом запуске TUI)

## Сборка

```bash
make build
```

Сборка через Makefile внедряет версию и штамп времени через `-ldflags`:
- `VERSION` (по умолчанию `v8.5.1`, переопределяется: `make build VERSION=v8.5.2`)
- `BUILD_TIME` (UTC-метка момента сборки, RFC3339)

Голый `go build` без Makefile оставит версию `dev` — это маркер нерелизной сборки.

## Установка

```bash
sudo make install
```

Бинарник копируется в `/opt/amberguard/agl`. Конфигурация создаётся автоматически при первом запуске. При первом старте также генерируются криптографические префиксы маршрутов веб-стука и устанавливается конфиг logrotate.

## Запуск

### TUI-панель (интерактивное управление)

```bash
sudo /opt/amberguard/agl
```

### Демон ловушек (systemd-юнит `agld_tarpit.service`)

Управляется автоматически из TUI через `tarpitctl`. Ручной запуск:

```bash
sudo ./agl --tarpit-daemon
```

### Наблюдатель простоя (systemd-юнит `agld_watcher.service`)

Управляется декларативно: жив, пока включён тумблер `web_server_enabled` в SETTINGS; при выключенном сервере процесс завершается сам. Рокировка портов не влияет на жизненный цикл наблюдателя. Ручной запуск:

```bash
sudo ./agl --watcher
```

### Автообновление сервера (systemd-юниты `agld_autoupdate.service` / `agld_autoupdate.timer`)

Управляется декларативно: включение тумблера `auto_update_enabled` в SETTINGS создаёт юниты и активирует таймер; выключение — останавливает и удаляет их. Ручной прогон одного цикла:

```bash
sudo ./agl --autoupdate
```

## CLI-ключи

```bash
sudo ./agl --version      # Версия и штамп сборки
sudo ./agl --info         # Интерактивная инфопанель (пути, статусы, канал спасения)
sudo ./agl --info --plain # Плоский текстовый вывод для --info (без псевдографики)
sudo ./agl --autoupdate   # Oneshot-цикл обновлений ОС (вызывается таймером)
sudo ./agl --lang ru|en   # Язык интерфейса на этот запуск (не сохраняется)
```

## Режимы запуска

| Режим                    | Команда               | Назначение                                                       |
| ------------------------ | --------------------- | ---------------------------------------------------------------- |
| Демон ловушек            | `agl --tarpit-daemon` | Менеджер ВСЕХ ловушек, лог-конвейеры, IPC                        |
| Наблюдатель              | `agl --watcher`       | 30-сек тикер простоя админа, веб-стук, сервер спасения           |
| Автообновление (oneshot) | `agl --autoupdate`    | Цикл обновлений: apt-get update + dist-upgrade + проверка ребута |
| TUI-пульт                | `agl` (без флагов)    | Интерактивная панель, слушателей НЕ запускает                    |
| Версия                   | `agl --version`       | Версия и время сборки                                            |
| Инфо                     | `agl --info`          | Интерактивная панель: канал спасения, службы, пути, версия       |

## Автообновление сервера

- Тумблеры в SETTINGS (группа SYSTEM): `auto_update_enabled` и `auto_update_reboot` — бинарные переключатели, инвертируются стрелками ←/→.
- При включении AGL декларативно создаёт `agld_autoupdate.service` (Type=oneshot) и `agld_autoupdate.timer` (ежедневно в 04:00 + случайный разброс до 1 часа, Persistent=true); при выключении — останавливает и удаляет их.
- Цикл: `apt-get update` → подсчёт пакетов через simulate → `apt-get dist-upgrade -y` (DEBIAN_FRONTEND=noninteractive, force-confdef/confold) → проверка `/var/run/reboot-required`.
- Отложенный ребут через `shutdown -r +1` выполняется только при включённом `auto_update_reboot`; иначе событие логируется, администратор перезагружает вручную.
- Параллельные запуски исключены flock-локом; все события пишутся в главный журнал под компонентом `AUTOUPDATE`.

## Резервное копирование

- Запускается из TUI (меню BACKUP). Асинхронная генерация трёх файлов в сессионную директорию `/backup/ГГГГ.ММ.ДД_ЧЧ.ММ/`.
- Файлы: `*_server_snapshot.tar.gz` (системные конфиги), `*_package_list.txt` (dpkg), `*_forensics_logs.tar.gz` (SIEM-логи).
- Цели настраиваются через `/etc/amberguard/backup_targets.json` (создаётся автоматически с дефолтами).
- FIFO-ротация: при дефиците места (<15%) старые сессии удаляются автоматически.

## Принципы (ДНК продукта)

- **Декларативность:** админ пишет намерение — демон приводит систему к факту (reconciliation loop, self-healing).
- **Fail closed:** любой сбой роняет систему в безопасное состояние, никогда — в открытое.
- **Трёхфакторный статус:** декларация → подтверждение демона → факт на диске.
- **Полная автономность:** без внешних веб-серверов и облаков; один бинарник — весь периметр.
- **Предохранители единственности:** flock-локи для демон-режимов; второй экземпляр умирает с ALERT.
- **POSIX Atomic Write:** все фиксации на диск через tmp → fsync → rename.

## Дисклеймер

Только для тестовых и изолированных серверов.

Комплекс модифицирует системные конфигурации (`sshd_config`, UFW, sysctl),
создаёт systemd-юниты и управляет сетевыми правилами.

Перед установкой на production-хост:
- Убедитесь, что понимаете последствия каждой операции
- Имейте резервный канал доступа (канал спасения веб-стука или физический консольный доступ)
- Протестируйте в изолированной среде
- Сделайте полный бэкап системы
