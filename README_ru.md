# Amber Guard Laboratory

Автономный оборонный комплекс для Linux-хоста. Обнаруживает, обманывает, истощает, защищает, спасает.

## Возможности

- **Дегтярная Яма (Tarpit)** — SSH-ловушка с вариативными задержками; базовый капкан + декларативный пул мульти-ловушек.
- **Броня периметра (Armor)** — авто-обнаружение служб и rate-limit рубежи UFW с корпоративными сигнатурами; самовосстановление после ребута.
- **Рокировка портов (Castling)** — переезд SSH на скрытый порт с авто-бэкапом, откатом и анти-локаутом администратора.
- **Канал спасения (Web Rescue)** — автономный HTTPS-сервер веб-стука (TLS 1.2+, bcrypt): вход даже при закрытом периметре.
- **Вотчер простоя (Watcher)** — детекция сессий и «испепеление» скрытых правил при простое администратора.
- **Форензика** — SIEM-хроника касаний и истощения: страны, поведение, TCP-отпечатки сканеров.
- **Автообновление сервера (v8.4.0)** — автономный суточный цикл обновлений ОС (apt-get dist-upgrade в noninteractive-режиме), детекция необходимости ребута и отложенная перезагрузка; планируется systemd-таймером, декларативно включается из SETTINGS.

## Требования

- **ОС:** Ubuntu 22.04+ / Debian 12+ (systemd, UFW, Netfilter)
- **Go:** 1.21 или новее
- **Права:** root (привилегии для привязки портов < 1024 и управления systemd)
- **Опционально:** `geoip-bin` + `geoip-database` (страны в логах; устанавливается автоматически при первом запуске TUI)

## Сборка

```bash
make build
```

Сборка через Makefile внедряет версию и штамп времени через `-ldflags`:
- `VERSION` (по умолчанию `v8.4.0`, переопределяется: `make build VERSION=v8.4.1`)
- `BUILD_TIME` (UTC-метка момента сборки, RFC3339)

Голый `go build` без Makefile оставит версию `dev` — это маркер нерелизной сборки.

## Установка

```bash
sudo make install
```

Бинарник копируется в `/opt/amberguard/agl`. Конфигурация создаётся автоматически при первом запуске.

## Запуск

### TUI-панель (интерактивное управление)

```bash
sudo /opt/amberguard/agl
```

### Демон ловушек (systemd-юнит `agld_tarpit.service`)

Управляется автоматически из TUI. Ручной запуск:

```bash
sudo ./agl --tarpit-daemon
```

### Наблюдатель простоя (systemd-юнит `agld_watcher.service`)

Запускается автоматически при рокировке портов. Ручной запуск:

```bash
sudo ./agl --watcher
```

### Автообновление сервера (systemd-юниты `agld_autoupdate.service` / `agld_autoupdate.timer`)

Управляется декларативно: включение тумблера `auto_update_enabled` в SETTINGS создаёт юниты и активирует таймер; выключение — останавливает и удаляет их. Ручной прогон одного цикла:

```bash
sudo ./agl --autoupdate
```

## CLI-ключи

```bash
sudo ./agl --version      # Версия и штамп сборки
sudo ./agl --info         # Служебная геометрия (пути, юниты)
sudo ./agl --autoupdate   # Oneshot-цикл обновлений ОС (вызывается таймером)
sudo ./agl --lang ru|en   # Язык интерфейса на этот запуск (не сохраняется)
sudo ./agl --plain        # Чистый текстовый вывод для --info (без псевдографики)
```

## Режимы запуска

| Режим                    | Команда               | Назначение                                                       |
| ------------------------ | --------------------- | ---------------------------------------------------------------- |
| Демон ловушек            | `agl --tarpit-daemon` | Менеджер ВСЕХ ловушек, лог-конвейеры, IPC                        |
| Наблюдатель              | `agl --watcher`       | 60-сек тикер простоя админа, веб-стук                            |
| Автообновление (oneshot) | `agl --autoupdate`    | Цикл обновлений: apt-get update + dist-upgrade + проверка ребута |

| Версия                   | `agl --version`       | Версия и время сборки                                            |
| Инфо                     | `agl --info`          | Геометрия путей из compile-time констант                         |

## Автообновление сервера (v8.4.0)

- Тумблеры в SETTINGS (группа SYSTEM): `auto_update_enabled` и `auto_update_reboot` — бинарные переключатели, инвертируются стрелками ←/→.
- При включении AGL декларативно создаёт `agld_autoupdate.service` (Type=oneshot) и `agld_autoupdate.timer` (ежедневно в 04:00 + случайный разброс до 1 часа, Persistent=true); при выключении — останавливает и удаляет их.
- Цикл: `apt-get update` → подсчёт пакетов через simulate → `apt-get dist-upgrade -y` (DEBIAN_FRONTEND=noninteractive, force-confdef/confold) → проверка `/var/run/reboot-required`.
- Отложенный ребут через `shutdown -r +1` выполняется только при включённом `auto_update_reboot`; иначе событие логируется, администратор перезагружает вручную.
- Параллельные запуски исключены flock-локом; все события пишутся в главный журнал под компонентом `AUTOUPDATE`.

## Принципы (ДНК продукта)

- **Декларативность:** админ пишет намерение — демон приводит систему к факту (reconciliation loop, self-healing).
- **Fail closed:** любой сбой роняет систему в безопасное состояние, никогда — в открытое.
- **Трёхфакторный статус:** декларация → подтверждение демона → факт на диске.
- **Полная автономность:** без внешних веб-серверов и облаков; один бинарник — весь периметр.

## Дисклеймер

⚠️ Только для тестовых и изолированных серверов.
Комплекс модифицирует системные конфигурации (`sshd_config`, UFW, sysctl),
создаёт systemd-юниты и управляет сетевыми правилами.
Перед установкой на production-хост:
- Убедитесь, что понимаете последствия каждой операции
- Имейте резервный канал доступа (канал спасения веб-стука или физический консольный доступ)
- Протестируйте в изолированной среде
- Сделайте полный бэкап системы
